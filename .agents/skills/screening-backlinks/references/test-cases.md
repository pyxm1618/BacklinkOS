# 回归测试

以下行为必须成立：

1. `discovering-backlinks` 传来的 source project、Organic Traffic、AS、backlinks_num、first_seen、last_seen、Semrush historical Follow 等事实直接使用，不重新查询。
2. 不出现“Quick I Ching 是否有资格”“当前项目是否适合”等判断。
3. 免费且当前可获得、最终为 Follow、页面可索引 → 进入外链总表，获取方式=`免费`。
4. 必须 reciprocal backlink，但不收费，且最终为 Follow、页面可索引 → 进入外链总表，获取方式=`免费换链`。
5. 必须付款才能得到合格 Follow 链接 → 回收站。
6. 免费层 Nofollow / UGC / Sponsored，付费层才 Follow → 回收站，不进入总表。
7. 免费提交按钮存在，但无法确认最终公开页是否有合格 Follow 外链 → `不确定`，进入待确认。
8. 最终页明确 noindex → 回收站。
9. DR 很低或流量很低，但满足免费 + Follow + 当前可获得 + 可索引 → 仍可进入总表；这些指标只影响排序。
10. 同一域名的 Profile 和 Directory 有不同操作入口时，可保存为两个机会。
11. 已在总表中的同一机会再次被发现 → 更新证据/最近验证，不追加到“新增记录”。
12. AI-only、SaaS-only、地域等只记录为条件，不根据任何具体推广项目淘汰。
13. 用户说“继续/全部执行/筛完/做完”时，只处理一个样本批次后停止属于失败；必须持续处理直到 `待筛选=0`，除非遇到明确外部阻塞。
14. `待筛选>0` 时不得回复“全部完成”。若被阻塞，必须同时报告剩余待筛选数量和阻塞点。
15. 允许网络级批量回收，但必须有共同运营方/品牌/模板/机制或公开调查证据；只凭域名命名相似不得批量淘汰。
16. 网络级批量规则必须保存匹配规则、处理状态、原因、证据 URL、核验日期和适用范围，并让后续同规则候选自动继承状态。
17. 已验证批量案例：`seo-anomaly-*` 可依据公开网络调查及运营方自身 PBN/backlink 服务说明批量回收；`bhs-links-*` 可依据公开页面标题/描述中的 Hardcore Black Hat SEO / @bhs_links 网络说明批量回收。
18. 每轮写入后必须重新统计 `待筛选`；只要仍大于 0，全量模式继续下一批。
