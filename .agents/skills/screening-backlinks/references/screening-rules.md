# 筛选规则

## 获取方式

只使用四种：

- **免费**：无需付款，也不强制给对方回链。可选的 Featured、加速审核、首页曝光等付费升级不改变“免费”。
- **免费换链**：无需付款，但必须给对方 reciprocal backlink。
- **付费**：想获得符合要求的 Follow 外链必须付款。免费层只有 Nofollow、付费层才 Follow，也归这里。
- **不确定**：当前无法确认是否存在合格的免费/换链路径。

## 处理结果

处理结果与获取方式分开：

- **正式机会**：当前可执行，且获取方式为免费/免费换链，最终直链 Follow、页面可索引。
- **付费排除**：获得合格 Follow 必须付款。
- **回收**：当前机制明确不满足目标，例如免费路径 Nofollow/UGC/Sponsored、无外部 URL、入口失效、noindex、死亡站，或有闭环证据证明是垃圾/恶意/卖链网络。
- **待确认**：关键事实无法闭环，但没有足够负面证据进入回收。

## 证据优先级

证据优先级按**事实类型**决定，不使用一条万能来源排序。

### 获取方式、价格、资格

1. 当前实际提交/注册/付款流程；
2. 当前官方 Submit / Pricing / FAQ / Terms；
3. 当前可复核的同路径实例；
4. 可信的当前第三方实测；
5. 历史发现数据与推断。

### 技术输出：href / rel / Follow / noindex / canonical

1. 当前具体 listing/result 结果页 DOM / HTML；
2. 当前同路径、同模板的具体结果页 DOM / HTML；
3. 能指向具体当前结果页并给出可复核技术观察的第三方实测；
4. 官方对技术属性的具体说明；泛化营销文案仅作线索；
5. Discovery 历史 Semrush；
6. 推断。

对 `rel` / Follow 这类技术输出，**当前具体结果页 DOM/HTML 证据优先、高于泛化官方宣传**。官方营销/宣传中的“Dofollow”承诺不能覆盖当前 listing 已观察到的 `rel=nofollow`。如果第三方给出当前具体页面的技术实测，但官方宣传相反，而当前 DOM 暂时无法直接取得，则记录冲突并进入 `待确认`，优先补 DOM，不机械采用任何一方。

历史 `is_follow` 是发现事实，不是当前免费路径结论。

## 最终链接

必须验证当前同一路径产生的公开结果页。

正式机会需要同时满足：

1. 页面公开可访问；
2. 页面允许被搜索引擎索引；
3. 有直接指向外部目标网站的 `<a href>`；
4. `rel` 不含 `nofollow`、`ugc`、`sponsored`。

以下进入**回收**：

- 免费/免费换链路径最终为 Nofollow、UGC、Sponsored；
- 只有站内跳转或跟踪包装链接，不能得到直接外链；
- 没有 Website URL；
- 提交/发布入口已明确关闭或站点死亡；
- 最终页明确 `noindex`；
- 有闭环证据证明属于 PBN、恶意站、自动垃圾网络或明确卖链网络。

只有付费才能得到合格 Follow 时进入**付费排除**，不要写成回收。

## 缺失事实纪律

- **没找到不等于回收。** 搜索不到入口、页面或规则，只说明当前证据不足。
- **AS=0 不等于回收。** AS/DR/流量只用于排序或参考。
- **历史 0 Follow 不等于回收。** 当前机制仍需验证。
- 历史 100% Follow 也不等于当前免费 Follow。
- CAPTCHA、必须登录、邮箱验证、人工审核、暂时无法生成样例都不等于回收。
- 域名命名相似、低 AS、同 IP、同 TLD 或“看起来像垃圾”都不能单独支持网络级回收。

遇到关键结果无法确认时进入 `待确认`，并记录缺失维度与下一步。

## Source URL 补证

如果 domain-level 事实不足以识别历史 backlink 机制，而精确来源页可能显著缩小范围，Screening 返回：

`source_url_enrichment_required | referring_domain | source_projects | reason`

由 `discovering-backlinks` 按 handoff contract 补 `source_url / target_url / anchor / source_rel_observation` 等事实。Screening 不自己猜 source URL，也不因为 enrichment 暂不可得而强判回收。

## 网络级判定

网络/PBN/卖链批量判定必须有共同运营方、品牌、模板、机制、明确商业卖链行为或可靠公开调查证据。规则必须保存：匹配规则、处理结果、原因、证据 URL、核验日期、适用范围。证据失效时重新核验。

## 数据迁移安全

运行表之间迁移状态时，**迁移顺序：目标写入 → 回读确认 → 源清理**。

- 先把完整目标记录写入目标表；
- 回读目标行并确认关键字段存在；
- 之后只清理源表中由当前流程拥有的数据单元格；
- 含 `ARRAYFORMULA`、公式列、计算路由列的表禁止整行清除；
- 每批迁移后重新核对总量、空状态和互斥状态集合。

目标写入、回读、源清理三步缺一不可。

## 限制条件

AI-only、SaaS-only、地区、公司资料、原创文章、GitHub 项目等只写入“条件/限制”。Screening 不替任何具体项目判断能否满足。
